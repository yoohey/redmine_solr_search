# 検証のまとめ

このプラグインを、開発のあいだにどう確かめたかを、1枚にまとめたものです。数字は、どれも開発環境で測った例です。導入先での速さや結果を約束するものではありません。導入先では、[マニュアルの第6章](manual.md#第6章状態タブ)と[第14章](manual.md#第14章検索の品質の手入れ)の方法で、同じことを確かめられます。

## 1. 権限：見てはいけないものが出ないか

いちばん重く見ているところです。Redmineがその利用者に見せている範囲と、検索で出る範囲が一致するかを、2つの方法で確かめています。

| 確かめたこと | 方法 | 結果（1.0.0の前） |
|---|---|---|
| 検索の絞り込み（Solrのfilter query）が通す文書の集合が、Redmineの閲覧の判定と一致するか | サンプルデータの7人（管理者、各ロールのメンバー、非メンバー、匿名）と、ロール・トラッカー・プライベート注記・グループ・公開と非公開・プロジェクトの終了とアーカイブなどを変えた20の条件（利用者との組で34通り）で、集合を1件ずつ比べる。問い合わせの書きかた9通りでも同じか | 34通りすべてで、**取りこぼし0・余り0**。9通りとも同じ |
| 検索画面に出るものが、その利用者に見えるものだけか | 17の語×利用者の96通りで、画面に出た結果を、Redmineの判定で数え直す（チケット、注記、添付ファイル、プライベートの印） | **漏れ0**（注記・添付ファイルも0） |
| 外部ソースが、許可と紐付けとロールの権限どおりに出るか | 許可していないプロジェクトへの紐付けの拒否、権限の片方だけを持つロール、非メンバーと匿名のロールなど | 期待どおり（直す前のコードでは、ここで不具合を見つけて直しました） |

- 表示の直前にも、Redmineの判定でもう一度確かめます（[2段階の判定](manual.md#検索時の2段階セキュリティ)）。
- 外部の文書には、ファイルサーバー側のアクセス権を持ち込みません。見せる相手は、外部ソースの許可と紐付け、Redmineの権限で決まります（[権限の考え方](manual.md#22-権限の考え方)）。

## 2. 検索の質：見つけるべきものを見つけるか

正解をあらかじめ書いた検索のセットで、結果を点数にしています（管理ページの「検索ログ」タブと同じ仕組み。[正解つきの検索](manual.md#第14章検索の品質の手入れ)）。

| セット | 中身 | 結果 |
|---|---|---|
| 網羅（その語を含むものを、すべて見つけるか） | 利用者ごとに、語を含むすべての入れ物（チケット、Wikiページなど）を正解にする | 再現率 **0.9905**、適合率 **1.0000**、漏れ0（23,550件のうち23,327件）。足りない分は、本文を取り出さないと決めている圧縮ファイル（zip）などです |
| 順位（上に出るべきものが上に出るか） | 人が書いた32の検索と、上位5件に出るべき正解 | MRR **0.8144**、上位に正解が出たのは32のうち29 |

- 確かめのために、わざと悪くした場合も流しています。権限の絞り込みを外すと漏れが出て適合率が落ち、並びの重みから題名を外すとMRRが0.47に落ちることで、この点数が実際に違いをとらえることを確かめました。

## 3. 量と速さ

チケット10万件、注記約53万件、添付ファイル約1万件、外部ソース20個（計10万文書）の環境で測りました（Solrには約52.5万文書）。24スレッドのPCで、文書の本文は短いものです。

| 測ったもの | 結果 |
|---|---|
| 検索1回の時間 | 8〜134ミリ秒（利用者ごとに5回の中央値。見られるプロジェクトが多い人ほど長い）。外部ソースを足しても、ほとんど変わらない |
| 受けられる検索 | Redmineの1プロセスで、1秒あたり約17〜19件。それ以上は順番待ちで遅くなるが、失敗はしない。詰まるのはRedmineのプロセスのCPUで、プロセスの数を増やして広げられます（[性能の目安](manual.md#182-性能の目安)） |
| 全件の作り直し | 約51.5万文書で102秒（添付ファイルの本文は別） |
| 検索ログ | 50万行・クリック20万行があっても、同時の書き込みで、数の食い違いや二重の記録はなし |

## 4. 対応する版

| 部品 | 確かめた版 | 確かめたこと |
|---|---|---|
| Redmine | 5.1.12・6.0.11・6.1.5・7.0.2（開発は6.1） | 起動とマイグレーション、インデックスの作成、管理ページの全画面、検索の件数が、6.1と同じ。5.1では、権限の集合の比較もすべて6.1と同じ。画面のHTMLの形も版ごとに比べています |
| Apache Solr | 9.10.1（開発）・10.1.0 | コレクションの作成、インデックスの作成、検索の件数、権限の絞り込み、差分の反映、外部ソースの検索が同じ（ManifoldCFからの取り込みは9.10.1だけ） |
| Apache Tika Server | 4.1.0 | 添付ファイルと外部の文書の本文の取り出し |
| Apache ManifoldCF | 2.31 | フォルダと、OSでつないだSMBの共有フォルダからの取り込み |

- 軽いテスト（データベースもSolrも使わない部分の398本）は、GitHub Actionsで、対応するRedmineに合わせた4通りのRubyとRailsの版で、変更のたびに流しています。
- 動作要件は[README](../README.md#動作要件)にまとめています。

## 5. 同梱のDockerで、最初から動くか

公開するものとまったく同じ中身を組み立て、`git clone`からREADMEの手順どおりに試しています。

| 確かめたこと | 結果 |
|---|---|
| `docker compose up -d`から検索できるまで（イメージの取得の時間は除く） | 約2分（`try-minimal`は112秒、`try-full`は114秒） |
| サンプルデータの7人での権限 | 漏れ0、再現率0.9905 |
| 新しく作ったチケットが、自動で検索に出るまで | 594秒（初期の設定は10分おきの差分の反映） |
| 片付け（`docker compose down -v`） | コンテナもボリュームも残らない |

## 6. 確かめていないこと

- SharePointなど、フォルダ・SMBの共有フォルダ以外の取り込み元。
- PostgreSQL以外のデータベース。
- 英語の文書の検索の質（日本語向けの解析に合わせて作っています）。
- 今動いているRedmineに足す形（`minimal`・`external`・`full`）を、同梱のDockerから最初から最後まで通すこと（部品ごとには確かめています）。
