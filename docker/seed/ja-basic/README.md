# データセット ja-basic

最初に作った基本のデータセット。日本語のチケットを約3,000件入れ、権限の異なるユーザーを5人用意している。添付ファイルは、JRの路線ごとに駅名を並べたもの。

**目的**：Redmineのデータと添付ファイルを全文検索したときに、次の点を確かめる。

- 権限が漏れないこと
- 形式ごとに本文を取り出せていること
- 日本語の解析の癖

中身とIDは、実行した日に関係なく毎回同じ。日付は、実行した日を「今日」として動く。

同梱のDockerの、Redmineごと試す組み合わせ（`try-*`・`windows`）では、初回の起動のときに自動で入る。期待値は[expected/summary.md](expected/summary.md)。

## 中身のばらつき

- **ステータス**
  - 古いチケットほど「終了」「却下」が多く、新しいほど「新規」「進行中」が多い。
  - 履歴（ステータスの変化）と注記は、作成日から更新日の間に並ぶ。
  - 注記の約4%は後から編集されていて、`journals.updated_on`が動く。
- **長さ**
  - 件名：短いもの・普通・長いものが混ざる。
  - 説明：1行・数文・Markdown（表、コードブロック入り）・数千字の議事録や障害報告が混ざる。
  - 注記：0件から20件以上まで。
- **日付**：約半数に期日がある（期限切れ、今週、先のものが混ざる）。
- **ガントチャート**
  - search-platformのM1〜M4と、dept-docsの棚卸し第1期〜規程改定に、バージョンと親子チケットの計画がある。
  - 計画には、開始日・期日・予定工数・進捗率・先行後続の関連が付いている。
  - 「今日」を基準に、完了・進行中・未着手のタスクに分かれる。
- **その他**：カテゴリ、対象バージョン、チケット間の関連（関連・重複・ブロック）、Wikiの版の履歴。

## 添付ファイル（[attachments/](attachments/)）

JRの17路線について、駅名を並べたファイルを1つずつ用意している。駅名で検索すると、どのファイルがヒットすべきかがすぐ分かる。

- **正解表**：[lines.yml](attachments/lines.yml)。東京や新宿など複数の路線にある駅は、複数のファイルにヒットするのが正しい。
- **形式**：ランダムに割り当てている。
  - 本文が取れるもの：txt、md、csv、json、xml、html、pdf、docx、xlsx、pptx、zip（中にtxtとcsv）、Shift_JISのtxt・csv
  - 本文が取れないもの：png、スキャン風のPDF（`_スキャン.pdf`）。ファイル名でしかヒットしない。
- **社外秘のファイル**：`社外秘_新線計画（仮称）.docx`。架空の駅名（翠嶺台など）が入っていて、プライベートチケットにだけ添付する。
- **付け方**
  - チケットの約15%に1〜3個添付する。半分は作成時、半分は後から注記と一緒に添付する。
  - 文書の約70%、Wikiの一部にも添付する。
- **生成**：ファイルごとの形式と本文は[manifest.yml](attachments/manifest.yml)にある。ファイルは[generate.py](attachments/generate.py)で作ってコミット済み（作り直し方はスクリプトの先頭に記載）。

## 点検（[verify.rb](verify.rb)）

次の点を、OK/NGで確かめる。

- 件数が約3,000件であること
- 実行した時刻のまま残っている日時がないこと
- 注記がすべて作成日から更新日の間にあること
- 編集された注記があること
- 社外秘ファイルがプライベートチケットにだけ付いていること
- プライベートチケットにはすべて「社外秘」が入っていること
- ガントチャートに、完了・進行中・未着手のタスクがあること
- プライベート注記を書いたのが、その権限を持つ人だけであること
